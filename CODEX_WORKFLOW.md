# Рабочий процесс
## Перед изменением
Проверь git status --short, git branch --show-current, git remote -v. Прочитай подходящий раздел спецификации и существующий код. Для неочевидного изменения сформулируй критерий приёмки и небольшой план.
Ветки: feature/<slug>, bugfix/<slug>, docs/<slug>. Базовая ветка нового проекта — main; в существующем репозитории проверь фактическую default branch.

## Реализация и проверка
Выполняй задачу до проверяемого результата. Тестируй изменённое поведение, особенно отмену, ошибки провайдера и сохранность данных.
Когда создан NexsusVKVideo.sln:
```powershell
dotnet restore NexsusVKVideo.sln
dotnet build NexsusVKVideo.sln -c Release --no-restore
dotnet test NexsusVKVideo.sln -c Release --no-build
```
Проверяй exit code каждой команды. UI дополнительно проверяй по дизайн-гайду. Нет Windows/SDK/доступа — укажи, что не проверено, и используй CI, если доступен.

## GitHub
Изменения фиксируй небольшими логическими коммитами: feat:, fix:, refactor:, docs:, test:, build:.
Перед staging просмотри diff и убедись, что нет токенов, cookies и локальных данных.
Если задача включает доставку в GitHub, выполни commit, push ветки и создание PR через доступный коннектор или gh. При отсутствии авторизации сохрани локальный результат и сообщи, какой вход требуется.
PR содержит проблему, результат, проверки, ограничения и rollback. Проверь CI для последнего коммита; исправь относящиеся к задаче ошибки. Для merge и публикации нужны соответствующие указания пользователя.
