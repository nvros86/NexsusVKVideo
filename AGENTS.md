# Правила разработки NexsusVKVideo
## Назначение
Работай как сопровождающий разработчик. Завершай согласованную задачу: реализация, проверка, документация и краткий отчёт. Не выдавай планы, заглушки или непроверенные утверждения за реализованные возможности.

## Архитектурные инварианты
- Используй WPF + MVVM; Core не зависит от UI, WebView2, HTTP и хранилища.
- App — composition root. Infrastructure реализует контракты Core. Модули не обращаются друг к другу напрямую.
- Не добавляй второй UI framework, общий service locator, глобальное изменяемое состояние или runtime загрузку непроверенных DLL.
- Не блокируй UI: асинхронный I/O, отмена, ограниченная параллельность, освобождение ресурсов.
- Реальные возможности VK сначала проверяй по официальной документации; не выдумывай API и прямые ссылки на потоки.
- Отдельно маркируй демонстрационные данные. AI Center до своей фазы показывает состояние «Скоро».
- PNG используется для визуального сравнения, не как фон или готовый интерактивный интерфейс.

## Выполнение задачи
1. Определи критерии готовности, затронутые файлы и зависимости. Для простой правки достаточно короткого плана.
2. Сохрани чужие изменения. Создай отдельную ветку при необходимости; не переключай её поверх чужой незавершённой работы.
3. Вноси минимальный законченный набор изменений. Исправляй первопричину, избегай несвязанных переписываний.
4. Запускай относящиеся к изменению проверки. Для C# — restore/build/test; для UI также ручная проверка размеров и состояний.
5. Обнови один change record и только документацию, которую изменение делает неверной.
6. Проверь diff и секреты перед коммитом. Используй явные пути для staging. Коммит/PR выполняй в рамках запроса и доступных прав.
7. В отчёте: результат, проверки с фактическим статусом, ограничения, следующий конкретный шаг.

## Границы
Не удаляй чужие файлы, не делай force push или reset --hard, не публикуй релиз и не объединяй PR без соответствующего разрешения пользователя. Не спрашивай повторно о уже разрешённых действиях. При отсутствии доступа продолжай доступную локальную работу и точно называй блокировку.
Не отключай проверки ради зелёного статуса; не утверждай, что тесты прошли, если они не запускались.
