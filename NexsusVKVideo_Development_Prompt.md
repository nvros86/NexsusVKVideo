# Development prompt — NexsusVKVideo
## Происхождение
Восстановлено по доступной переписке «Промт для NexsusVKVideo», 19.09.2026.
Это согласованная реконструкция требований, а не побайтовая копия прежнего вложения, которое недоступно.

## Исходная идея пользователя
Создать лёгкое Windows-приложение, похожее на браузер для просмотра VK Video, изначально быстрое, с модульной структурой для последующего расширения. Предусмотреть GitHub, инструкции Codex и записи изменений для отката.

## Задание разработчику
Реализуй NexsusVKVideo поэтапно. Основной стек — C#, WPF, MVVM; применение MVC понимается как разделение ответственности, а не требование web MVC.
Создай независимое ядро, адаптер VK, оболочку, модульные функции, тесты и воспроизводимую сборку.
Стартовый пакет не заявляет готовность интеграции или наличие доступа ко всем функциям VK.

## MVP
- Home: доступный контент провайдера либо явно подписанный демонстрационный каталог.
- Search: поиск через документированный поддерживаемый способ; пагинация, отмена предыдущего запроса, пустой результат и повтор при ошибке.
- Player: официальный web/embed сценарий, если допустим; при ограничениях — понятная ошибка и переход в системный браузер.
- Library: локальная история; Favorites: добавление и удаление доступных видео без дублей.
- Settings: тема, очистка истории/кэша, настройки приватности и сведения о версии.
- Навигация Home/Search/Library/Favorites/AI Center/Settings. AI Center зарезервирован и не обещает реализованных AI-функций.
- Вход в аккаунт только через поддерживаемый flow; не запрашивать пароль VK в собственных полях приложения.

## Скорость и надёжность
Показывай оболочку до загрузки сети; один активный player/WebView на MVP.
Ленивая загрузка модулей и изображений, ограниченный кэш, виртуализация длинных списков.
Цели для измерения, не заявленные результаты: холодный запуск оболочки <=2 секунд на тестовой машине с SSD; отсутствие синхронного сетевого I/O в UI; стабильная память после 20 циклов открытия/закрытия плеера.
Фиксируй модель машины, сборку Release, методику и медиану минимум 5 запусков.
Обрабатывай offline, timeout, rate limit, expired auth, private/deleted video, отсутствие WebView runtime.

## Границы
Не обходить DRM, ограничения доступа и права владельцев контента. Загрузки видео, сторонние провайдеры, плагины из сети и AI — отдельные будущие задачи.
Не строить собственный движок браузера. Не добавлять сервер, телеметрию или облачную синхронизацию без продуктового требования.

## Приёмка
Сборка на Windows; тесты Core; навигация клавиатурой; отсутствие зависания UI; понятные состояния ошибок; отсутствие секретов в Git; проверенный change record и откат. Визуальная приёмка — по docs/DESIGN_IMPLEMENTATION_GUIDE.md.
