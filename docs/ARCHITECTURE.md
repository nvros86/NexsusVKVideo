# Архитектура
## Решение
WPF + MVVM. App — composition root и оболочка, Core — модели и контракты, Infrastructure — I/O, Modules — прикладные возможности.
Выбор WPF фиксирует одну реализацию из ранее обсуждавшихся WPF/WinUI вариантов.

## Зависимости
App -> Core, Infrastructure, Modules.
Infrastructure -> Core.
Modules -> Core (UI-модули могут ссылаться на WPF, но не на Infrastructure).
Core -> только базовые .NET библиотеки. Tests -> тестируемый проект.
Регистрация реализаций через DI в App; не разрешать зависимости через глобальный контейнер.

## Контракты
IVideoProvider: поиск/получение метаданных/получение поддерживаемого playback descriptor.
IPlaybackService: открыть/остановить/освободить player; не выдаёт неподтверждённые stream URL.
IHistoryRepository и IFavoritesRepository: локальное хранение с уникальным ключом provider+videoId.
ISettingsStore: версионируемые настройки. IModule: идентификатор, маршруты, регистрация сервисов, запуск и завершение.
DTO провайдера маппятся в Core; provider errors преобразуются в типизированный результат.

## Поток
View -> command ViewModel -> use case/контракт Core -> адаптер -> результат -> UI dispatcher.
CancellationToken передаётся по цепочке. При новом поиске отменяется старый; устаревший ответ не меняет экран.
HTTP-клиент переиспользуется. Retry ограничен для безопасных запросов; учитывается rate limit. Отмена не показывается как ошибка.
Хранилище и browser profile находятся вне репозитория, в пользовательских данных приложения.
Схема данных версионируется; миграции тестируются на копии. WebView освобождается при закрытии/смене сценария.
Не вводить event bus, динамические плагины и абстракции без реального потребителя. Значимые решения фиксировать в docs/decisions/.
