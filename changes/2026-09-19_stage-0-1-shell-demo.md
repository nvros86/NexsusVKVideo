# Этап 0.1 — навигационная оболочка и demo Home

Дата: 2026-09-19

Цель: реализовать навигацию WPF, явно подписанный демонстрационный Home и безопасную проверку документированного VK Video widget.

База Git: `150c699 feat: add stage 0 WPF scaffold`.

Компоненты: App XAML/MVVM, визуальные ресурсы, документация решения.

Изменение: добавлены маршруты Главная/Поиск/Библиотека/Избранное/AI Center/Настройки, demo-карточки и состояния плеера. Один явно подписанный пример из официальной документации VK открывает `vk.ru/video_ext.php?oid=…&id=…` в единственном WebView2. Инфраструктурный allowlist требует HTTPS, точный host `vk.ru`, точный embed path и `oid`/`id`; другие top-level URL блокируются. Кнопка fallback открывает в системном браузере только валидную страницу `https://vk.ru/video-…`. AI Center показывает «Скоро» без фоновых запросов.

Проверки (команда/сценарий, фактический результат): `dotnet restore NexsusVKVideo.sln -m:1` — успешно; `dotnet build NexsusVKVideo.sln -c Release --no-restore -m:1` — успешно, 0 warnings/0 errors; `dotnet test NexsusVKVideo.sln -c Release --no-build -m:1` — успешно, 13/13. Официальная документация [VK Video widget](https://dev.vk.com/ru/widgets/video) проверена: она публикует формат iframe и публичной video-page, использованные в allowlist.

Данные и совместимость: хранилище, миграции, авторизация и API-запросы не добавлялись. WebView2 использует профиль в `%LocalAppData%\NexsusVKVideo\WebView2`, который не попадает в Git. Demo-данные не сохраняются.

Откат (commit/порядок, резервная копия, проверка): выполнить `git revert <commit>` этого изменения, затем restore/build/test. Данных для резервного копирования нет.

Ограничения: встроенный WebView2 отображает только официальный widget и не обходится DRM, авторизация или ограничения VK. Каталог, поиск и выбор пользовательских видео не реализованы. Визуальная автоматизация среды не видит нативные окна, поэтому screenshot-review, resize и DPI-проверка остаются ручными.
